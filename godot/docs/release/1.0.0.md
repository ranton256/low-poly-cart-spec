# Low Poly Cart 1.0.0 — release record

The Godot port, complete against the design document: all fourteen Acceptance
Checklist items pass as named conformance tests at their stated tolerances
(G2/V7), all 64 GDD scenarios are covered (G1: 63 verified, 1
visual-with-baseline, none deferred), and **the ambiguity register —
`godot/docs/AMBIGUITIES.md`, the deliverable this repository exists to
produce — is complete: fourteen entries, none open.** A12 was settled by
amending the design document itself (the two-prop pin is a transient, not a
trap, and the GDD now says so); A14 — what item 14's "replayed" quantifies
over — was raised and resolved by measurement during this milestone's own
review.

## §14 ladder, as run for this release

**Phase 0 — gate.** `tools/test.sh`: 22 suites, 8 checkers, the step bench,
and the six-state visual gallery, all green at the tagged commit. No
unchecked tasks; both M8 changes archived.

**Phase 1 — export.** Four targets from one commit via `tools/export_all.sh`
(sizes and SHA-256s in its output, recorded in the archived change):
Web (wasm 36 MB / pck 10 MB; 19.05 MB gzip-9 against the 25 MB budget),
macOS universal .app, Linux x86_64, Windows x86_64.

**Phase 2 — smoke.** The artifact smokes itself: `LPC_SMOKE=1` boots to the
countdown unaided, takes control on GO, drives the lap suite's phase table
through the real input path, banks a lap, writes a capture
(`LPC_SMOKE_SHOT`), and exits 0 — anything less exits nonzero.

- macOS: run against the exported (and then the signed) .app — banked
  15.05 s at tick 1142, clean exit both times.
  Capture: `docs/progress/2026-08-30-m8-smoke-macos.png`.
- Web: served locally, loaded in a real browser session on a **cold** cache
  (48.3 MB transferred, verified via resource `transferSize`): engine start
  at **0.62 s**, countdown inside the following second — the ≤ 5 s bound
  holds with an 8× margin on the reference machine, network transfer
  excluded. Capture (from the live canvas):
  `docs/progress/2026-08-30-m8-smoke-web.png`.
- **Windows and Linux: built and checksummed, NOT smoke-tested** — this
  release was cut on a single Mac. Their smoke is the same one-liner and is
  owed before distributing those artifacts:
  `LPC_SMOKE=1 LPC_SMOKE_SHOT=smoke.png ./lowpolycart.x86_64` (or the .exe),
  expect exit 0 and a capture.

**Phase 3 — sign.** The macOS app is signed with
`Developer ID Application: Richard Anton (2U8TFZTUT5)` under the hardened
runtime with a secure timestamp; `codesign --verify --deep --strict` passes
and the bundle satisfies its Designated Requirement. **Notarization is NOT
done** — this machine holds no App Store Connect credentials — so
`spctl` currently says `rejected (Unnotarized Developer ID)`, as expected.
The credential holder finishes with:

```
xcrun notarytool store-credentials AC_PASSWORD --apple-id <id> --team-id 2U8TFZTUT5
ditto -c -k --keepParent build/macos/LowPolyCart.app LowPolyCart.zip
xcrun notarytool submit LowPolyCart.zip --keychain-profile AC_PASSWORD --wait
xcrun stapler staple build/macos/LowPolyCart.app
spctl -a -t exec -vv build/macos/LowPolyCart.app   # expect: accepted, Notarized Developer ID
```

then validates on a machine that has never seen the certificate (§14's
hazard note), which this machine, by definition, cannot be.

**Phase 4 — tag.** `config/version` is 1.0.0. The annotated tag `v1.0.0` is
cut as the milestone's final act, after the Critic's verdict, on the commit
recorded in `docs/progress/2026-08-30-m8-export-record.txt` as the build
source — deferred deliberately so a review remediation cannot orphan it (the
deviation is recorded in the archived change's tasks).

## What shipped

Countdown → GO handover at 4.0 s; the specified kart physics at a fixed
60 Hz, byte-stable on replay and measured 0.0000 wu / 0.0000 s apart across
real 30/60/144 fps rendering (see A14 for what "replayed" must mean); collision stop-shove-shake with the reverse-out
guarantee and the (now correctly documented) transient pin; soft boundary
with grass past fog's end; chase camera with speed-widened FOV; full HUD —
countdown, timer with hold-and-flash lap banking, speedometer, north-up
minimap with masked markers; seeded prop fields, save/load layouts
(byte-identical round-trips, desktop file + web download); live tuning from
`data/tuning.json` on the next tick; Reset Kart.
