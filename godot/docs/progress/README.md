# Visual proof

Committed screenshots showing what the game actually looked like at a point in
time. Generated by `tools/capture.sh`, never by hand.

**Mandatory for a milestone. Expected for any task that changes what the player
sees or how the game plays.** See [CONSTRAINTS §12 Review](../../../CONSTRAINTS.md).

The reason is narrow and practical: a test suite proves behaviour, and a green
suite tells you nothing about whether the thing on screen looks right. Those are
different failures needing different evidence. A screenshot is also the only
artefact that survives a claim like "the highlighting works now" without
requiring someone to rebuild the project to check.

```bash
tools/capture.sh                                            # main scene -> gallery/
tools/capture.sh res://scenes/main.tscn docs/progress/x.png 30
```

`gallery/` is scratch and git-ignored. This directory is committed. `docs/` has
a `.gdignore`, so none of these images are imported or shipped in an export.

Name files `YYYY-MM-DD-what-it-shows.png`. Dates, not numbers — inserting a
capture later renumbers everything after it and churns the directory.

**Capture the first one before there is anything to see.** An empty scene proves
the path works end to end while nothing is at stake, and becomes the zero
baseline every later capture is compared against. Record its measured noise
floor here — two captures of the same scene with nothing changed between them —
because that is the number any future comparison threshold must sit a small
multiple above. It should be at or near zero; if it is not, something is
non-deterministic and the harness is the bug, not the threshold.
